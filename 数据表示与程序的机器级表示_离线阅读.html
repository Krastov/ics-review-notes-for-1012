数据的表示与程序的机器级表示：考前复习材料

适用范围：以 CS:APP 第 3 版第 2、3 章的常见内容为主。汇编采用 x86-64、AT&T 语法；函数调用采用 Linux 的 System V AMD64 ABI。考试日期按当前日期计算为 2026 年 10 月 12 日。

这份材料不含练习题。少量数值和代码只用于说明规则，可以直接跳到每节的“背诵句”。你已确认学到这两部分，但没有提供老师的具体考纲，所以这里覆盖常见的完整范围，并把较靠后的内容标为“补充”。没有把“教材包含”当作“你已经学会”。

使用方法：先通读正文，弄清每项规则的条件，再背最后的提要。时间紧时，先掌握整数表示与转换、浮点数、寻址与 mov、条件码与跳转、过程调用与栈、数组与结构体；扩展内容随后补。正文中的“固定 w 位”指机器位模式模型，不自动等同于合法的 C 表达式。

第一部分：数据的表示

1. 先分清四件事：位模式、类型、数值、地址

位模式是一串 0 和 1。类型规定用什么规则解释这些位。数值是解释的结果。地址说明数据放在内存的哪个位置。

同一个 8 位模式 11111111，解释成无符号整数时是 255，解释成补码有符号整数时是 −1。位没有改变，解释规则变了。浮点数又使用另一套规则。

地址也是一个数，但“地址的数值”和“那个地址存放的数据”必须分开。例如地址 0x1000 处放着整数 7：0x1000 是位置，7 是内容。指针保存地址，解引用读取或修改地址所指向的对象。

字节 byte 通常是 8 位 bit。内存通常按字节编址：相邻两个地址差 1，表示相邻两个字节。一个 4 字节整数占用连续 4 个字节。

背诵句：位模式本身不决定有符号性；类型决定解释。地址表示位置，内存内容表示该位置保存的数据。

2. 二进制、十六进制与字节序

每一位十六进制对应 4 位二进制。十六进制 0～9 对应 0～9，A～F 对应 10～15。前缀 0x 表示十六进制。

十六进制 二进制 十六进制 二进制
0 0000 8 1000
1 0001 9 1001
2 0010 A 1010
3 0011 B 1011
4 0100 C 1100
5 0101 D 1101
6 0110 E 1110
7 0111 F 1111

二进制转十六进制：从右向左每 4 位分一组，高位不够时补 0。十六进制转二进制：逐位展开成 4 位。计算地址偏移时也可以先转十进制，但不要把 0x10 当作十进制 10，它是 16。

字节序只讨论一个多字节对象的各个字节怎样排列。

  • 小端序 little endian：最低有效字节放在最低地址。
  • 大端序 big endian：最高有效字节放在最低地址。

例如 32 位整数 0x12345678 从地址 A 开始存放：

地址 小端序 大端序
A 78 12
A+1 56 34
A+2 34 56
A+3 12 78

x86-64 使用小端序。字节序不把每个字节中的比特倒过来。内存里显示 78 56 34 12，重建小端整数时得到 0x12345678。

字符串按字符顺序存储，不按“整个字符串是一个整数”的方式倒排。C 字符串以空字符 '\0' 结束；字符串字面量 "abc" 的存储包含 a、b、c、\0 四个字符。

背诵句：小端低字节在低地址，大端高字节在低地址；字节序调整的是字节之间的顺序。

这些数值是平台约定，不是所有 C 实现一律如此。Windows x64 常采用 LLP64：long 是 4 字节，指针仍是 8 字节。考试题写明平台时按题目；按 CS:APP Linux 环境时通常按上表。

背诵句：类型大小依赖平台；Linux x86-64 中 int 4、long 8、指针 8。数组的大小与数组指针的大小不同。

4. 位运算与逻辑运算

运算 名称 核心规则
~x 按位取反 每位 0、1 互换
x & y 按位与 两位都为 1 才为 1
x | y 按位或 至少一位为 1 就为 1
x ^ y 按位异或 两位不同时为 1
!x 逻辑非 x 为 0 得 1，非 0 得 0
x && y 逻辑与 两个操作数都非 0 才得 1
x || y 逻辑或 至少一个操作数非 0 就得 1

按位运算逐位进行，结果不是只有 0 或 1。C 中逻辑运算结果是 int 类型的 0 或 1。

逻辑与、逻辑或有短路：x && y 在 x 为 0 时不求值 y；x || y 在 x 非 0 时不求值 y。按位与、按位或不具有这种条件性跳过右侧求值的规则。不要依赖按位操作两个操作数的先后求值顺序。

常用恒等式，在相同位宽下成立：

  • x ^ x = 0；x ^ 0 = x。
  • x & 0 = 0；x | 0 = x。
  • x & 全 1 = x；x | 全 1 = 全 1。
  • x & ~x = 0；x | ~x = 全 1。
  • ~(x & y) = ~x | ~y。
  • ~(x | y) = ~x & ~y。

掩码 mask 用来选定某些位。低 k 位掩码的数学值为 2^k−1。读取第 k 位可用无符号数右移 k 位再与 1；置位用或，清位用与取反掩码，翻转用异或。下标从最低位 0 开始。

C 代码里构造掩码时要照顾类型和移位范围。1 << 31 的左操作数通常是有符号 int，不能随意当作通用合法写法；固定 32 位无符号掩码通常用 1U，64 位常用 1ULL。移位数仍必须小于左操作数经提升后的位宽。

背诵句：位运算逐位处理；逻辑运算判断零与非零并产生 0 或 1。只有 &&、|| 保证相应的短路规则。

5. 左移、逻辑右移、算术右移

在固定 w 位机器模型中：

  • 左移：所有位向高位移动，低位补 0，移出的高位丢弃。
  • 逻辑右移：向低位移动，高位补 0。
  • 算术右移：向低位移动，高位补原符号位。

左移 k 位在保留低 w 位的意义下相当于乘 2^k。无符号右移 k 位等于除以 2^k 后向下取整。补码算术右移也对应向负无穷取整，而 C 有符号整数除法是向 0 截断。

例如 −7 / 2 在 C 中是 −3；补码 −7 算术右移 1 位得到 −4。因此负数的右移不能直接替代 C 的除法。

C 与机器指令的边界：

  • 无符号数右移规定为逻辑右移。
  • 按本课程常用的传统 C 语境，负有符号数右移是实现定义的；x86 编译环境通常采用算术右移。
  • 无符号左移按相应位宽取模；按这里的 C11 规则，有符号左移要求左操作数非负，且乘以 2 的相应幂后仍能由结果类型表示，否则行为未定义。不能把“硬件会截断”写成“C 一定合法”。
  • 移位数为负或大于等于提升后的左操作数位宽，C 行为未定义。
  • x86 的某些移位指令会只使用计数的低若干位，不能用这一点替 C 表达式解释非法移位。

背诵句：shr 高位补零，sar 高位补符号；负数算术右移向下取整，C 整数除法向零截断。

6. 无符号整数表示

w 位位向量记为 b_(w−1)…b_1 b_0，其中每个 b_i 取 0 或 1。

无符号数值：

U = Σ[i=0 到 w−1] b_i × 2^i。

范围：0 ≤ U ≤ 2^w−1。

全 0 表示 0，全 1 表示最大值 UMax = 2^w−1。每个位模式对应唯一的无符号整数。

背诵句：无符号整数所有位都提供非负权重，w 位范围是 0 到 2^w−1。

7. 补码有符号整数表示

补码 two's complement 的最高位权重是负的，其余各位权重为正。

T = −b_(w−1) × 2^(w−1) + Σ[i=0 到 w−2] b_i × 2^i。

范围：−2^(w−1) ≤ T ≤ 2^(w−1)−1。

名称 数值 位模式
TMin −2^(w−1) 100…000
TMax 2^(w−1)−1 011…111
−1 −1 111…111
0 0 000…000

补码负数比非负数多一个。没有单独的“负零”。对同一 w 位模式：最高位为 0 时，补码值与无符号值相同；最高位为 1 时，补码值 = 无符号值 − 2^w。

负数 x 的 w 位补码可由 2^w+x 求出；也可先写 |x| 的二进制，再按位取反加 1。这里的“取反加一”必须在同一个位宽内进行。

将 x 视为固定 w 位补码值时，逐位取反后的补码值恒为 −x−1；取负的机器位模式是 ~x+1。但 TMin 的正数相反数超出范围，所以对 TMin 取负的机器结果仍是 TMin；C 中有符号 −TMin 溢出时是未定义行为。

背诵句：补码最高位权重为 −2^(w−1)；最小值比最大值的相反数再小 1；TMin 无法在同位宽有符号类型内取正。

8. 同位宽的有符号与无符号转换

按本课程常用的补码环境，保持同样的 w 位模式重新解释：

  • 有符号 x 转无符号：x ≥ 0 时仍是 x；x < 0 时得到 x+2^w。
  • 无符号 u 转补码有符号：u ≤ TMax 时仍是 u；u > TMax 时按补码解释为 u−2^w。

例如 32 位 −1 转 unsigned 得到 2^32−1。它没有变成绝对值 1。

C 标准层面：转到无符号类型按目标范围模 2^w 调整；不能被目标有符号类型表示时，传统 C 标准将结果或相应信号处理留给实现。因此“位模式保持不变”主要是这里采用的机器环境规则，不应写成所有 C 实现的无条件保证。

背诵句：同位宽转换通常改变解释，不改变位。负数转 unsigned 按模数回绕，−1 变为无符号最大值。

9. 整数提升、混合运算与比较

不能仅看变量原来的声明就判断表达式如何计算。C 常先做整数提升，再做通常算术转换。

整数提升：char、short 等较窄整数类型通常先提升到 int；若 int 不能表示该类型所有取值，才提升到 unsigned int。常见 32 位 int 环境中，unsigned char、unsigned short 也能提升到 int。

常见混合有符号与无符号转换规则：先比较转换等级与范围。

  1. 如果同为有符号或同为无符号，较低等级转为较高等级。
  2. 若无符号类型等级不低于有符号类型，有符号操作数转为该无符号类型。
  3. 若有符号类型等级更高，且能表示无符号类型所有值，无符号操作数转为该有符号类型。
  4. 否则双方转为高等级有符号类型对应的无符号类型。

同等级 int 与 unsigned int 混合时，int 转 unsigned int。于是 −1 < 1U 为假，因为 −1 被解释成很大的无符号值。

但“只要出现 unsigned，整个表达式就是 unsigned”不成立。在 Linux LP64 中，64 位 long 能表示所有 32 位 unsigned int，因此 long 与 unsigned int 运算通常转为 long。

sizeof 得到的 size_t 常参与无符号计算。若 n 是有符号整数，和 sizeof 的结果比较时可能发生转换。无符号减法如 0U−1U 不得到负数，而得到最大值。循环计数器若是 unsigned，条件 i >= 0 永远为真。

背诵句：比较之前也会发生类型转换；先看提升和共同类型，再看大小关系。

10. 扩展、截断与转换顺序

从窄位宽扩展到宽位宽：

  • 无符号零扩展：高位补 0，保留无符号数值。
  • 补码符号扩展：高位复制原符号位，保留有符号数值。

例如 8 位 11111111：零扩展到 16 位是 0000000011111111，数值为 255；符号扩展是 1111111111111111，补码值仍是 −1。

截断到 k 位：保留低 k 位，丢弃高位。若按无符号解释，所得值为原整数模 2^k；若按补码解释，再用目标位宽的最高位判断符号。截断可能改变值，也可能改变正负。

同时改变位宽和符号类型时，不要省略中间过程。典型 CS:APP 推导按“源类型决定如何扩展，然后按目标类型解释”追踪。例如 signed char 的 −1 转为 32 位 unsigned int，在常见环境中得到 0xffffffff，而不是 0x000000ff；先转成 unsigned char 再转 unsigned int 才得到 255。

背诵句：零扩展保无符号值，符号扩展保补码值；截断只留低位；源类型会影响扩大位宽时填入什么。

11. 整数加法、减法、溢出

固定 w 位无符号加法：结果为 (x+y) mod 2^w。若数学和不小于 2^w，丢掉最高进位。C 无符号算术也遵循模运算规则。

无符号加法检测：设 s=x+y 已按该无符号类型保存，s < x 表示发生回绕，也等价于 s < y。此处 x、y、s 必须确实在相同的目标无符号算术域中；窄类型提升后要留意实际计算位宽。

补码机器加法使用同一个二进制加法器，只是解释方式和溢出判断不同。

  • 两个非负数相加得到负数：正溢出。
  • 两个负数相加得到非负数：负溢出。
  • 一正一负相加，不会发生补码加法溢出。
  • 符号位的进位与符号位的出位不同，也可判断有符号加法溢出。

最高位有进位不能直接等同于有符号溢出。无符号主要看是否超出 0…2^w−1；有符号看是否超出 TMin…TMax。

减法 x−y 在位模式层面可用 x+(~y+1)。有符号减法溢出发生在：x、y 符号不同，而且结果符号与 x 不同。

C 的有符号溢出是未定义行为。不能把机器补码回绕当作 C 源程序的普遍保证，也不能可靠地写“先让有符号数溢出，再检查结果”作为可移植检测。

安全的范围推导是在运算前比较。例如有符号加法：y>0 时检查 x > TMax−y；y<0 时检查 x < TMin−y。这里边界式本身没有越界。

背诵句：无符号运算按模回绕；补码硬件保留低位；C 有符号溢出未定义。加法同号看结果反号，减法异号看结果反号。

12. 整数乘法、除法与常数优化

数学上两个 w 位数的完整乘积最多需要 2w 位。普通固定 w 位乘法只保留低 w 位，因此可能溢出。

同一组位模式按有符号或无符号解释，其乘积的低 w 位相同，完整 2w 位结果的高半部分可能不同。这解释了为什么只取低位时常能共用乘法硬件。

乘以常数可以组合移位、加法、减法。例如 10x = (x<<3)+(x<<1)，15x=(x<<4)−x。这是数学分解；写成 C 时仍要满足各步运算的合法性。编译器可能使用 lea 来计算这样的线性组合。

C 整数除法向 0 截断。余数满足 x = (x/y)×y + x%y；余数为 0 或与被除数 x 同号，绝对值小于除数绝对值。除以 0 未定义；TMin / −1 的商无法表示，也未定义。

无符号除以 2^k：逻辑右移 k 位。非负有符号数同样可直接右移。负数若要用算术右移实现向 0 截断，需要先加偏置 2^k−1：

q = (x + bias) 算术右移 k；其中 x<0 时 bias=2^k−1，x≥0 时 bias=0。

适用前提是 0≤k<w，且使用与这里相符的位宽和算术右移语义。它修正了负数原本向负无穷取整的偏差。

背诵句：乘法低位相同、高位可能不同；除法向零截断；负数除以 2 的幂时，先加偏置再算术右移。

13. 浮点数的总体结构

二进制浮点数把数写成符号、有效数和二进制指数：V = (−1)^s × M × 2^E。

IEEE 754 常见编码由三段组成：符号位 s、阶码字段 e、小数字段 f。注意 e 是存储的无符号字段，E 是解码后的实际指数；f 是字段内容，M 是实际有效数。这两组符号不要混用。

格式 总位数 s e f bias 规格化有效精度
float / binary32 32 1 8 23 127 24 位
double / binary64 64 1 11 52 1023 53 位

若阶码有 k 位，bias=2^(k−1)−1。规格化数有隐含的前导 1，所以有效精度比存储的小数字段多 1 位。

浮点数不是“先写二进制整数再随便放一个小数点”。必须根据 e 的类别确定 E 和 M。

背诵句：浮点编码看 s、e、f，实际数值看符号、M、E；先判类别，再套公式。

14. 规格化、非规格化与特殊值

设小数字段有 n 位，把它视为整数 F，则 frac = F / 2^n。

类别 阶码 e 小数字段 f 实际解释
规格化数 既非全 0，也非全 1 任意 M=1+frac，E=e−bias
非规格化非零数 全 0 非全 0 M=frac，E=1−bias
±0 全 0 全 0 由符号位区分 +0 与 −0
±∞ 全 1 全 0 由符号位决定正负无穷
NaN 全 1 非全 0 非数 Not a Number

非规格化数又称 subnormal 或 denormalized。它没有隐含前导 1；指数固定为 1−bias，而不是 −bias。这使最小规格化数与较小的非规格化数平滑衔接，称为渐进下溢。

零有两个编码，但普通数值比较中 +0 == −0 为真。符号仍可能影响某些运算，例如 IEEE 754 环境下 1/(+0) 为 +∞、1/(−0) 为 −∞。

NaN 不等于任何值，包括自身。若 x 为 NaN，则 x==x 为假，x!=x 为真；x<y、x<=y、x>y、x>=y 这些普通有序比较都为假。不要由“x=y 为真”。

背诵句：e 中间是规格化，全 0 是零或非规格化，全 1 是无穷或 NaN；非规格化指数是 1−bias。

15. 浮点数范围、间距与精确性

规格化最小实际指数 Emin=1−bias，最大实际指数 Emax=(2^k−2)−bias。

在正数中：

  • 最小正非规格化数 = 2^(1−bias−n)。
  • 最大非规格化数 = (1−2^(−n))×2^(1−bias)。
  • 最小正规格化数 = 2^(1−bias)。
  • 最大有限数 = (2−2^(−n))×2^Emax。
参数 binary32 binary64
最小正非规格化数 2^(−149) 2^(−1074)
最小正规格化数 2^(−126) 2^(−1022)
最大有限数 (2−2^(−23))×2^127 (2−2^(−52))×2^1023
1 附近向上的间距 2^(−23) 2^(−52)

在同一个规格化指数区间 [2^E, 2^(E+1)) 中，相邻可表示数的间距为 2^(E−n)。数的绝对值越大，绝对间距通常越大。因此“表示范围很大”不等于“任意大整数都精确”。

若精度为 p 位，则从 −2^p 到 2^p 的所有整数都可精确表示；超过这个范围仍有一些整数可精确表示，但不再每个整数都可以。float 的 p=24，double 的 p=53。

有限二进制小数对应约分后分母为 2 的幂的有理数，但是否能由某个具体浮点格式精确表示，还要看有效位数和指数范围。0.5 可以精确表示，十进制 0.1 不能用有限二进制小数精确表示。

背诵句：浮点数范围由指数控制，精度由有效位数控制；离零越远，相邻数的绝对间距越大。

16. 浮点数的编码与解码步骤

解码时严格按以下顺序：

  1. 按格式切分 s、e、f。
  2. 判断 e 是全 0、全 1，还是中间值。
  3. 求 frac=F/2^n。
  4. 按类别求 M 和 E。
  5. 求 V=(−1)^s×M×2^E；特殊值单独写。

编码一个普通非零数时：先取符号，将绝对值转成二进制；若可规格化，写成 1.xxx×2^E，求 e=E+bias，再保留规定数量的小数位并舍入。若太小，转入非规格化范围，以固定指数 1−bias 编码。

舍入可能导致有效数进位，例如 1.111… 舍入后成为 10.000…，此时必须再次规格化并增加指数。指数也可能因此越过有限范围。

背诵句：编码先写二进制科学计数法；解码先判阶码类别；舍入后还要检查是否进位。

17. 浮点舍入与运算性质

常见默认舍入是 round to nearest, ties to even：舍入到最近值，距离相等时选有效数最低保留位为 0 的值。

“偶数”指保留结果的最后一个二进制有效位为 0，不是在比较十进制整数是不是偶数。对于二进制截断位置，恰好一半意味着：第一舍弃位是 1，后面所有舍弃位都是 0。

判断最近偶数舍入：

  • 舍弃部分小于一半：保持。
  • 舍弃部分大于一半：增加一个最低保留位单位。
  • 恰好一半：最低保留位为 0 就保持，为 1 就进位。

若使用 guard、round、sticky 位：guard 是第一舍弃位，round 是第二舍弃位，sticky 表示后续位是否至少有一个 1。最近偶数的进位条件可写为 G=1 且 (R=1 或 S=1 或最低保留位=1)。

还存在向 0、向 +∞、向 −∞ 等舍入方向。C 的浮点转整数规则是向 0 截断，不要直接套用默认浮点算术舍入规则。

理解浮点运算时，可以按“先得到数学上的精确结果，再舍入到目标格式”建模。实际硬件可能用额外精度或融合运算，考试若指定精度与舍入方式，就以指定模型为准。

浮点加法、乘法一般不满足结合律。改变括号可能改变每一步舍入，从而改变结果。分配律也不普遍成立。大数加很小的数，结果可能仍是大数；两个接近的大数相减可能损失大量有效数字。

上溢表示结果太大，下溢表示太靠近零。下溢可能先产生非规格化数，再舍入到零，并非一进入下溢区域就立刻变成零。上溢如何处理也与舍入模式有关；默认最近舍入常得到无穷。

背诵句：默认最近偶数；每一步可能舍入，所以结合律和分配律不能直接套用。

18. 整数与浮点类型转换

以下按常见 32 位 int、64 位 long、IEEE 单双精度讨论。

转换 常见性质
int → double 所有 32 位 int 都能精确表示
int → float 范围通常足够，但可能失去精度
float → double 每个 float 值都有精确对应表示；NaN 的具体编码不必保持
double → float 可能舍入，也可能超出目标范围或进入下溢区域
long → double 范围通常足够，但 64 位整数可能失去精度
浮点数 → int / long 去掉小数部分，向 0 截断；截断后的值必须在目标范围内

C 中浮点转整数若结果不可表示，包括 NaN 和无穷，不能依赖某个固定返回值来解释，行为未定义。某条机器指令出现的特殊结果不构成 C 的保证。

double 超出 float 可表示范围时，也不要把平台常见的得到无穷写成所有 C 环境的无条件规则；考试若明确采用 IEEE 硬件转换模型，按指定模型判断。

类型转换与位模式重解释不同：把整数数值 1 转成 float 得到 1.0，其编码通常是 0x3f800000；把 0x00000001 直接作为 float 位模式解释，得到最小正非规格化数。数值转换要重新编码，位模式重解释不进行同样的数值转换。

背诵句：转 double 不一定都精确，要看源整数精度；浮点转整数向零截断，越界没有可依赖的 C 结果。

第二部分：程序的机器级表示

19. 从 C 程序到机器执行

常见编译链：源程序 → 预处理 → 编译成汇编 → 汇编成目标文件 → 链接成可执行文件。

汇编是一种接近机器指令的文本表示；机器码是处理器执行的字节编码。反汇编把机器码重新表示为汇编文本，但通常无法唯一恢复原始 C 源程序。多个不同的 C 表达式可能生成相同汇编；优化也可能删除变量、合并计算、改变控制结构。

程序运行中常见的状态：通用寄存器、程序计数器、条件码、内存。%rip 与当前指令序列有关；在常用 RIP 相对寻址中，基准是当前指令结束后的地址。%rsp 保存栈顶地址。

读取汇编时先关注“当前指令修改什么、从哪里读值”，再把它归纳成源代码结构。不要预先认定每个局部变量一定在栈里；优化后的局部量可能只在寄存器中，也可能根本没有独立存储位置。

背诵句：汇编描述机器状态的改变；反汇编恢复指令，不能唯一恢复原始源程序。

20. AT&T 语法与指令后缀

AT&T 常用写法：操作码 源操作数, 目的操作数。

  • 寄存器前加 %，如 %rax。
  • 立即数前加 $，如 $8、$0x10。
  • 内存操作数常写成 偏移(基址,索引,比例)。
  • 常用后缀 b、w、l、q 分别表示 1、2、4、8 字节。
后缀 英文 位宽 常见示例
b byte 8 movb
w word 16 movw
l long word 32 movl
q quad word 64 movq

后缀表示这条指令的操作宽度，不是 C 类型名称的保证。movl 操作 32 位，即使 Linux 中 C 的 long 是 64 位。浮点指令中的 ss、sd 另有含义，见后文。

例如 subq %rsi, %rdi 表示 %rdi = %rdi−%rsi；cmpq %rsi, %rdi 也按 %rdi−%rsi 设置条件码，但不保存减法结果。

Intel 语法常写目的在前，并且寄存器通常不带 %，立即数不带 $。阅读材料时先确认语法，不能把两种操作数顺序混用。

背诵句：AT&T 源在前、目的在后；b/w/l/q 对应 8/16/32/64 位。

21. 寄存器与部分寄存器

x86-64 常见的 16 个 64 位通用寄存器是：rax、rbx、rcx、rdx、rsi、rdi、rbp、rsp、r8～r15。

同一个寄存器有不同宽度的名字：

64 位 低 32 位 低 16 位 低 8 位
%rax %eax %ax %al
%rbx %ebx %bx %bl
%rcx %ecx %cx %cl
%rdx %edx %dx %dl
%rsi %esi %si %sil
%rdi %edi %di %dil
%rbp %ebp %bp %bpl
%rsp %esp %sp %spl
%r8 %r8d %r8w %r8b
%r15 %r15d %r15w %r15b

这些不是互相独立的存储空间，而是同一个寄存器的不同部分。

最重要的写入规则：

  • 写 64 位寄存器：更新整个 64 位。
  • 写 32 位子寄存器：更新低 32 位，并清零对应 64 位寄存器的高 32 位。
  • 写 16 位或低 8 位子寄存器：仅改对应低位，高位保持原值。

movl $−1, %eax 后，%rax 的位模式是 0x00000000ffffffff；movq $−1, %rax 后是 0xffffffffffffffff。

xor %eax,%eax 常用于清零 %rax，因为低 32 位清零的同时高 32 位也清零。仅把 %al 置零，并不保证 %rax 为零。

背诵句：写 eax 自动清 rax 高 32 位；写 ax、al 不会自动清剩余高位。

22. 立即数、寄存器与内存寻址

设 R[r] 是寄存器 r 的内容，M[a] 是地址 a 处按指令宽度读取的内存内容。

操作数形式 含义
$Imm 立即数 Imm
%r 寄存器的内容 R[r]
D(%rb) 地址 D+R[rb] 处的内存内容
(%rb,%ri,S) 地址 R[rb]+R[ri]×S 处的内存内容
D(%rb,%ri,S) 地址 D+R[rb]+R[ri]×S 处的内存内容
D(,%ri,S) 地址 D+R[ri]×S 处的内存内容

比例因子 S 只能取 1、2、4、8。有效地址公式：EA = D + base + index×scale。D 按字节计，不是按元素计。基址、索引通常使用 64 位地址寄存器。

括号常表示需要读取内存。例如 %rax 是寄存器里的值，(%rax) 是以这个值作为地址去读内存。若 %rax=0x1000，地址 0x1000 处保存 7，则 movq %rax,%rbx 得到地址 0x1000，movq (%rax),%rbx 得到数据 7。

普通 mov 不能用一个指令把内存直接搬到另一处内存，通常要先读到寄存器，再写出。普通算术指令也通常不能同时带两个显式内存操作数。字符串指令等特殊指令不属于这个简化规则。

立即数是输入值，不能作为写入目的。大多数带 64 位操作数的算术指令只能编码符号扩展的 32 位立即数；不能见到 q 后缀就认为所有 64 位常量都能直接放进去。movabsq 可以加载一般的 64 位立即数到寄存器。

背诵句：地址 = 偏移+基址+索引×比例；mov 遇括号通常读内存，偏移单位是字节。

23. mov：复制位与扩展

普通 mov 将源的指定位宽数据复制到目的，不做“自动按源 C 类型重新解释”。寄存器名字与后缀要匹配。

常见普通移动：movb、movw、movl、movq。

扩展移动的两个宽度字母分别指出源宽度和目的宽度：

指令 操作
movsbw 8 位符号扩展到 16 位
movsbl 8 位符号扩展到 32 位
movsbq 8 位符号扩展到 64 位
movswl 16 位符号扩展到 32 位
movswq 16 位符号扩展到 64 位
movslq 32 位符号扩展到 64 位
movzbw 8 位零扩展到 16 位
movzbl 8 位零扩展到 32 位
movzbq 8 位零扩展到 64 位
movzwl 16 位零扩展到 32 位
movzwq 16 位零扩展到 64 位

s 表示 sign extension，z 表示 zero extension。扩展指令的目的通常是寄存器。

32 位零扩展到 64 位不需要专门的 movzlq：写 32 位目的寄存器就会自动清高 32 位。例如 movl %edi,%eax 可把低 32 位复制到 eax，并使 rax 的高半部分为零。

movsbl 某字节,%eax 先得到 32 位符号扩展结果，但写 eax 又会清 rax 高 32 位。因此如果最终要得到 64 位的负数，需要 movsbq，或再进行 movslq 等 64 位符号扩展，不能只看“指令有 s”就认定整个 rax 都已符号扩展。

普通 mov 和上述扩展 mov 不修改条件码。

背诵句：mov 复制；movs 符号扩展，movz 零扩展；目的写 eax 仍然清 rax 高 32 位。

24. lea：计算地址表达式的数值

lea 是 load effective address。leaq D(%rb,%ri,S),%rd 算出 D+R[rb]+R[ri]×S，放进目的寄存器，不读取该地址的内存内容。

同样写着括号，mov 和 lea 的作用不同：

  • movq 8(%rax),%rdx：去地址 %rax+8 读 8 字节。
  • leaq 8(%rax),%rdx：把数值 %rax+8 放进 %rdx。

lea 可生成指针，也常用来做整数线性计算。如 leaq (%rdi,%rdi,4),%rax 计算 5×%rdi。它不能一次计算两个变量的乘积，也没有任意比例因子；比例只允许 1、2、4、8。

lea 不修改条件码。因此编译器可以使用它计算某些加法，又保留前面比较设置的条件码。

背诵句：lea 只算有效地址的数值，不访问该地址的内存，不改变条件码。

具体指令还带 b/w/l/q 等宽度后缀。二元指令会覆盖目的操作数原值；做反汇编时要记住某寄存器旧值何时已不存在。

常见惯用形式：xor %eax,%eax 清零；test %rax,%rax 判断是否为零及符号；neg 后接某些位操作可能构造掩码；lea、移位、加减可能实现常数乘法。

26. 移位与旋转：重点是 sal、shl、shr、sar

指令 操作
sal / shl 左移，低位补 0；二者作用相同
shr 逻辑右移，高位补 0
sar 算术右移，高位补符号位

常见 AT&T 写法是 salq $3,%rax 或 sarq %cl,%rax。可变移位计数一般使用 %cl，不是任意寄存器。64 位移位计数通常只取低 6 位；32 位移位计数只取低 5 位。因此机器指令的计数处理与 C 非法移位的规则不同。

移位指令可能改变条件码，具体哪些标志有定义取决于指令和实际计数。有效计数为 0 时，普通移位保留标志；OF 的定义也与计数有关。分析后续跳转时不要把“发生移位”概括为“所有条件码都能使用”。

左移再算术右移相同次数，可能把某个被移动到最高位的位扩展成掩码。这类代码要按每一步实际位宽解释，不能简单把两次移位相消。

背诵句：sal=shl，shr 补零，sar 补符号；可变计数通常在 cl。

27. 完整乘法与除法

下面均以 q 后缀的 64 位形式说明。

27.1 乘法

普通双操作数 imulq S,D 只保留低 64 位。单操作数形式会使用隐含寄存器：

指令 输入 输出
mulq S %rax 与 S，按无符号解释 完整 128 位乘积写入 %rdx:%rax
imulq S %rax 与 S，按有符号解释 完整 128 位乘积写入 %rdx:%rax

%rdx:%rax 是把两个寄存器拼成一整个 128 位数，高 64 位是 rdx，低 64 位是 rax，不是两个互相独立的结果。

mul 的 CF、OF 表示高半部分是否非零；完整有符号 imul 的 CF、OF 表示完整乘积是否能由低半部分符号扩展得到，也就是能否放进目标宽度有符号范围。不要用乘法后的 ZF、SF 去做没有定义依据的判断。

除法前必须构造正确的 128 位被除数。

  • 若原无符号被除数只有 64 位：放入 rax，把 rdx 清零。
  • 若原有符号被除数只有 64 位：放入 rax，执行 cqto / cqo，把符号扩展到 rdx:rax。

cqto 只根据 rax 的符号位填充 rdx：非负时 rdx 全 0，负数时 rdx 全 1。它不是把 rax 的数值复制进 rdx。

有符号除法的商向 0 截断，余数与被除数同号或为 0。除数为 0，或者商放不进目标寄存器，机器会产生除法异常。商和余数覆盖 rax、rdx，因此原值若还要用，必须预先保存。

32 位对应形式使用 edx:eax，符号扩展常用 cltd / cdq。

背诵句：完整乘积和除法被除数都用 rdx:rax；乘法高低半部，除法商余数；有符号除法先 cqto。

28. 条件码：ZF、SF、CF、OF

条件码是部分指令根据结果设置的状态，供后面的跳转、set、条件传送使用。

标志 名称 主要解释
ZF zero flag 结果是否为 0
SF sign flag 结果的最高位是否为 1
CF carry flag 无符号进位；减法时可表示需要借位
OF overflow flag 有符号运算是否越过可表示范围

同一条 add 或 sub 可能同时供有符号与无符号判断使用，但使用的标志不同。CF 不等于 OF。SF 仅是机器结果的符号位，有溢出时不直接等于数学结果的符号。

cmp S,D 按 D−S 设置条件码，不保存差值。test S,D 按 D&S 设置条件码，不保存与结果。test 会将 CF、OF 清零；ZF、SF 来自按位与结果。

test %rax,%rax 常用于判断 rax 是否为 0；test $1,%rax 可查看最低位是否为 0。它们不会修改 rax。

读取跳转条件时，要往前找最近一次实际修改相关条件码的指令。中间出现 mov、lea，比较标志仍可能有效；中间出现 add、sub、test 等，标志往往已被改写。

背诵句：cmp 是目的减源且不保存；test 是按位与且不保存；找条件码要找最近一次相关写入。

29. 条件跳转速查表

表中的“x 与 y”指前面刚执行 cmp y,x，也就是计算 x−y 的比较。

关系 有符号跳转 条件 无符号跳转 条件
x==y je / jz ZF=1 je / jz ZF=1
x!=y jne / jnz ZF=0 jne / jnz ZF=0
x<y jl / jnge SF≠OF jb / jnae CF=1
x<=y jle / jng ZF=1 或 SF≠OF jbe / jna CF=1 或 ZF=1
x>y jg / jnle ZF=0 且 SF=OF ja / jnbe CF=0 且 ZF=0
x>=y jge / jnl SF=OF jae / jnb CF=0

辅助跳转：js 判断 SF=1，jns 判断 SF=0；jo 判断 OF=1，jno 判断 OF=0。js 不等于一般的“有符号小于比较”，因为有符号比较可能要校正溢出。

口诀：有符号 less/greater 用 l/g，无符号 below/above 用 b/a；equal 用 e，not 用 n。

为什么有符号比较看 SF 与 OF：cmp 的减法可能溢出，单看结果的 SF 会出错；用 SF XOR OF 可以恢复有符号小于判断。

jmp 无条件跳转。条件跳转不负责比较，只读取现有条件码。

背诵句：有符号小于 SF≠OF，无符号小于 CF=1；有符号大于 ZF=0 且 SF=OF，无符号大于 CF=0 且 ZF=0。

30. setcc 与 cmovcc

setcc 把满足条件写成一个字节 1，不满足写成 0。例如 setl %al、sete %al。它只更新指定的 8 位，不会自动把整个 eax 或 rax 都变成 0 或 1。

如果需要完整 int 布尔值，常见后续指令是 movzbl %al,%eax，或者在比较之前先清零 eax 再执行 set。若比较后才用 xor 清零，也可能破坏比较条件码，必须留意顺序。

cmovcc 在条件成立时把源值送入目的寄存器，条件不成立时目的保持原值。它常用于条件表达式、最大最小值等，避免分支。

条件传送不是 C 短路求值的普遍替代。某些候选值的计算已经先执行；而且带内存源的 cmov 即使最后不写入目的，也可能先访问源内存。因此源指针可能无效或表达式有副作用时，不能随便把条件分支变成“都算出来，再 cmov”。

cmov 的目的为寄存器，不是普通内存目的；常见整数 cmov 没有 8 位形式。

背诵句：set 生成一字节 0/1；cmov 条件写寄存器；条件传送不能保证跳过候选值的计算或无效内存访问。

31. if、条件表达式、循环与 switch

31.1 分支

if 常变成“比较 → 条件跳转 → 某一段代码 → 汇合”。跳转经常指向条件的反面，例如源程序 if(x<y)，汇编可能用 jge 跳过 then 部分。还原 C 时应根据实际到达的代码判断，不要机械把跳转名称当作源条件。

条件表达式可能编译为分支，也可能为条件传送。编译结果受优化、候选计算代价、是否能安全提前计算等因素影响。

31.2 循环

  • do…while：先执行循环体，再判断是否回到开头，至少执行一次。
  • while：逻辑上先判断；常见汇编会先跳到判断位置，随后从判断跳回循环体。
  • for：可分成初始化、条件、循环体、更新；continue 通常要到更新部分，再做下轮判断。

识别循环要找向后跳转、循环变量的初值与更新、退出条件。编译器也可能用先判退出条件再进入 do…while 风格循环的转换，所以不能只凭“比较在后面”就认定原源程序一定是 do…while。

break 跳出当前循环；continue 跳到当前循环下一轮应该开始的控制位置。嵌套循环要分清跳转跨了哪一层。

31.3 switch 与跳转表

case 值密集时，可能用跳转表：计算 case 索引，检查范围，从表中取得目标，再间接跳转。case 值稀疏时，也可能生成比较链或其他结构。

常见范围检查：先计算 idx=x−最小case，再按无符号比较 idx 与最大合法索引。小于最小值时，负 idx 按无符号解释很大，也会被排除。

跳转表可能保存完整代码地址，也可能保存相对于表基址的 32 位偏移。若是偏移，通常还需要符号扩展并加回基址，不能把表中每项一律当成完整地址。

多个 case 可共享目标；没有 break 的 case 可能继续执行下一段；default 可能由范围检查直接进入。间接跳转在 AT&T 中常有 *，如 jmp *%rax。

背诵句：分支看实际控制流，循环看初始化、更新、条件；switch 表项可能是地址，也可能是相对偏移。

32. 栈与 push、pop、call、ret

栈遵循后进先出。x86-64 常见运行时栈向低地址增长，%rsp 保存当前栈顶地址。栈顶不是最大的地址。

普通 64 位形式可按以下状态变化理解：

指令 %rsp 变化 主要效果
pushq S −8 把值写到新栈顶
popq D +8 读取旧栈顶的值并写入目的
call 目标 −8 压入下一条指令地址，再转到目标
ret +8 取出栈顶返回地址并跳转
subq $N,%rsp −N 为当前过程预留 N 字节空间
addq $N,%rsp +N 回收 N 字节空间

call 压入的是“调用结束后继续执行的位置”，不是被调用函数的入口地址。ret 从当前栈顶取返回地址，所以执行 ret 前必须把 rsp 恢复到返回地址所在位置。

jmp 不压入返回地址，不能在普通调用模型里完全替代 call。尾调用优化可以先恢复当前函数状态，再以 jmp 转到另一个函数，由后者最终返回给原调用者。

push、pop、call、ret 不负责普遍保存或恢复所有寄存器；那些工作由调用约定和编译器生成的代码完成。上述普通形式也不改算术条件码。

背诵句：栈向低地址增长；call 压下一条指令地址，ret 弹返回地址；分配栈空间减 rsp，回收加 rsp。

33. 用绝对地址追踪调用中的栈

下面是专门用于说明地址变化的教学布局，不代表所有编译器都固定这样安排局部变量。

假设调用者执行 call f 前，rsp=0x1000。f 会预留 24 字节，局部变量 x 放在预留区偏移 8 的位置，随后 f 调用 g。

时刻 rsp x 的绝对地址 相对当前 rsp 的位置
调用者执行 call f 前 0x1000 尚未安排 —
f 刚进入 0x0ff8 尚未安排 栈顶是 f 的返回地址
f 执行 subq $24,%rsp 后 0x0fe0 0x0fe8 8(%rsp)
f 执行 call g，g 刚进入 0x0fd8 0x0fe8 16(%rsp)
g 已恢复自己的栈并 ret，回到 f 0x0fe0 0x0fe8 8(%rsp)
f 执行 addq $24,%rsp 后 0x0ff8 该局部空间已回收 栈顶是 f 的返回地址
f 执行 ret，回到调用者 0x1000 生命周期结束 —

x 的绝对地址在其有效期间没有因为 call 自动改变。改变的是 rsp，所以“同一个对象相对于当前 rsp 的偏移”会改变。若把 x 的地址 0x0fe8 放进参数寄存器交给 g，g 就可以通过该指针访问 x，而不必知道 f 把 x 写成了几(%rsp)。

地址跟踪始终写三列：寄存器当前值、对象绝对地址、当前指令实际访问的地址。只写“这是局部变量”容易把基准变化漏掉。

背诵句：call 改 rsp，不搬走已有局部对象；相对偏移变了，不等于对象的绝对地址变了。

34. System V 参数与返回值

以下先讨论普通整数与指针标量参数。不是所有结构体、向量或混合参数都能直接按同一张表分配。

第几个整数/指针参数 64 位寄存器 int 常用低 32 位形式
1 %rdi %edi
2 %rsi %esi
3 %rdx %edx
4 %rcx %ecx
5 %r8 %r8d
6 %r9 %r9d

超出可用寄存器的参数通过栈传递。若前 6 个都是简单整数/指针参数，刚进入被调用函数时第 7 个通常在 8(%rsp)，第 8 个在 16(%rsp)；0(%rsp) 是返回地址。函数再 push 或 sub rsp 之后，这些偏移随之改变。

普通整数或指针返回值在 rax；int 返回值常用 eax。不要假设一个窄返回值的所有未使用高位都能直接作为更宽的有符号结果。调用者根据返回类型处理有效位。

float、double 参数通常分别使用 xmm0～xmm7 这组寄存器，返回值通常在 xmm0。整数参数和浮点参数使用不同的寄存器序列；混合参数不能简单说“源码第 2 个参数一律在 rsi”。

较大的结构体返回常使用隐藏的结果地址参数：调用者预留结果空间，把地址交给被调用者，被调用者把成员写入该空间。小型结构体也可能由一个或多个寄存器返回。是否使用隐藏参数要根据具体结构体分类和汇编判断；不要把所有结构体返回都统一看成指针返回。

Windows x64 使用不同调用约定，常见整数参数序列为 rcx、rdx、r8、r9，并有影子空间等规定。本材料做题时使用上面的 System V 约定。

背诵句：System V 整数参数顺序 rdi、rsi、rdx、rcx、r8、r9；整数返回 rax，浮点返回 xmm0。

35. 调用者保存与被调用者保存

“保存”是说函数调用前后的值应该由谁负责维持，不是说寄存器只能被某一方使用。

分类 常见寄存器 责任
被调用者保存 callee-saved rbx、rbp、r12、r13、r14、r15 被调用函数若使用并修改，返回前恢复原值
调用者保存 caller-saved rax、rcx、rdx、rsi、rdi、r8、r9、r10、r11 调用者若还要旧值，调用前自行保存
栈指针 rsp 被调用者返回时应恢复调用者应见的状态

System V 常用的 XMM 寄存器也是调用者保存。

一个函数可以同时扮演两种角色：对于调用它的函数，它是被调用者；对于它内部调用的函数，它又是调用者。

因此 f 要在 call g 后继续使用某个值，可以把值放到自己负责保存的寄存器中，或保存到自己的栈空间。若 f 修改 rbx，它既可以让 rbx 跨过 g 的调用保留，又必须最终恢复 f 的调用者原来的 rbx。

背诵句：caller-saved 的旧值由调用者保；callee-saved 被改了就由被调用者恢复。一个函数对上下两层有不同角色。

36. 栈帧、帧指针、对齐与递归

栈帧 stack frame 是某次函数调用所使用的一段栈空间，可能包括返回地址、保存的寄存器、局部变量、临时值、传给其他函数的栈参数，以及对齐填充。

局部量需要上栈的常见原因：寄存器不够、局部量是数组或结构体、需要取得地址、值要跨函数调用保存。不是每个函数都有完整栈帧，也不是每个局部变量都在栈中。

rbp 可用作帧指针 frame pointer，提供较稳定的访问基准。典型序言是 pushq %rbp；movq %rsp,%rbp；再减小 rsp。典型结尾恢复栈与 rbp。leave 可按“rsp←rbp，再 pop rbp”理解。

优化后可以省略帧指针，以 rsp 加不同偏移访问局部对象。没有 rbp 不表示没有栈，也不表示不能调用函数。

普通 System V 标量调用的常见对齐要求是：call 前 rsp 是 16 的倍数；call 压入 8 字节后，函数入口处 rsp+8 是 16 的倍数。因此刚进入函数时 rsp 通常余 8，而不是余 0。更宽的栈上传递向量等场景可能要求更严格的对齐。

补充：System V 有 rsp 下方 128 字节的 red zone，某些叶子函数可利用它保存临时量而不调整 rsp；不能把它作为普通跨调用安全保存区。Windows 没有相同的通用红区约定。

递归的每次动态调用都有各自应保留的调用状态和局部对象。递归能正确返回依赖：到达终止条件、每层保存仍要用的数据、栈恢复正确。深度过大可能耗尽栈空间。

背诵句：栈帧按需要建立；rbp 可以省略；普通 call 前 rsp 对齐 16，入口 rsp+8 对齐 16；递归每层保存自己的调用状态。

37. 数组、指针与一维寻址

声明 T a[N]，若每个元素大小为 L 字节，首地址为 A，则：

&a[i] = A + i×L；整个数组大小是 N×L。

数组元素连续，元素之间的间距就是 sizeof(T)。如果 T 是结构体，sizeof(T) 已经包含结构体内部及尾部填充，数组元素间隔仍按完整 sizeof(T) 计算。

p+i 的步长由 p 的目标类型决定。int* 加 1 通常前进 4 字节，double* 加 1 通常前进 8 字节，char* 加 1 前进 1 字节。汇编地址计算使用字节，不会自动再按 C 元素缩放。

p[i] 等价于 *(p+i)；&p[i] 是地址，不读取元素；*p 是对象的值。

同一数组内两个元素指针相减，得到元素个数，不是字节差。可形成数组尾后 one-past 指针，用于边界比较，但不能解引用它。跨无关对象随意减指针或越界解引用，不属于 C 的合法数组操作。

int *p[3]：p 是含 3 个 int 指针的数组。int (*p)[3]：p 是指向含 3 个 int 的数组的指针。括号改变结合方式；后者 p+1 通常前进 3×4=12 字节。

背诵句：数组首地址加下标乘元素大小；指针加一走一个目标对象；汇编偏移按字节计算。

38. 二维数组与指针数组

38.1 连续二维数组

T a[R][C] 按行优先存放。每一行有 C 个元素，所有行连续。

&a[i][j] = A + (i×C+j)×sizeof(T)。

行间距是 C×sizeof(T)。a[i] 在多数表达式中可转为这一行首元素的指针，但底层没有一张单独的“行指针表”。取得 a[i][j] 可用固定行宽直接算地址。

可变长度数组的行宽由运行时参数决定，汇编可能出现乘法；固定常数行宽更容易被移位、lea 等组合计算。

38.2 指针数组

T *b[R] 中，每一项是一个指针，b 本身的连续部分是 R 个指针。每个指针指向的行可位于不同地方，行长也可不同。

访问 b[i][j] 通常先在 b 的第 i 项读出行指针，再按 j×sizeof(T) 访问该行。这里存在一次额外的指针读取。

类型 连续部分 获得一行起点的方法
T a[R][C] R×C 个元素 首地址 + i×行大小
T *b[R] R 个指针 读第 i 个指针

T** 不能直接当作 T[R][C] 的同类指针。连续二维数组退化后通常是指向行数组的指针 T (*)[C]。

背诵句：二维数组是行数据连续，指针数组是行地址连续；前者算偏移，后者先读行指针。

39. 结构体、对齐与填充

结构体成员按声明顺序布局，但成员之间可能插入填充 padding。对齐要求 a 表示对象起始地址应为 a 的倍数，不等于“对象大小一定是 a”。

常见 Linux x86-64 对齐：char 为 1，short 为 2，int/float 为 4，long/double/指针为 8。更复杂类型、显式对齐、打包属性可能改变这些约定。

标准结构体布局的常用计算流程：

  1. 从偏移 0 开始。
  2. 当前成员对齐为 a，则把当前偏移向上取到 a 的倍数。
  3. 记下该成员起始偏移，再加成员大小。
  4. 遍历全部成员。
  5. 将总大小向上取到结构体整体对齐的倍数，形成尾部填充。

向上对齐公式：align_up(x,a)=ceil(x/a)×a。

普通结构体整体对齐常取成员最大对齐要求。尾部填充使结构体数组的下一项也能满足对齐。

例如：

struct S {
    char c;
    int x;
    short y;
};

常见布局为 c 在偏移 0，占 1 字节；偏移 1～3 填充；x 在偏移 4，占 4 字节；y 在偏移 8，占 2 字节；偏移 10～11 尾部填充。整体对齐 4，总大小 12。

成员地址 = 结构体首地址 + 成员偏移。汇编中固定偏移常能帮助识别成员；先确认类型大小和对齐，不能只用成员大小相加来猜总大小。

重新安排成员顺序有时可减少填充，但会改变布局；普通自动布局下，不能擅自把编译器看成可随意重排成员。

背诵句：成员逐个对齐，末尾整体对齐；sizeof(struct) 包含尾部填充，用来保证数组下一项对齐。

40. 联合体、结构体参数与隐藏返回地址

联合体 union 的各成员共用存储区域，通常从相同起点开始。大小至少容纳最大成员，并满足整体对齐；常见计算是把最大成员大小向上取到最大成员对齐的倍数。

结构体成员各自占用不同的区域，联合体成员重叠。因此结构体大小不直接等于最大成员大小，联合体大小通常也不等于所有成员大小之和。

联合体能用于观察同一组存储的不同解释，但未写入成员的读取规则在 C、C++ 中有差别；讨论类型双关和位模式时不要把某语言的一条规则套到另一语言。可移植地复制对象位模式，通常使用字符访问或 memcpy，而不是任意强制转换后解引用。

结构体按值传参和传指针不同。按值传参给被调用者的是结构体值，修改形参本身不会修改调用者对象；传指针后可通过该指针修改对象。

结构体按值传参可能使用寄存器，也可能使用栈。较大返回对象常通过隐藏结果地址实现。还原此类代码要逐步确定：谁分配结果空间，哪个参数是隐藏地址，显式参数是否因此顺移，写入的各偏移对应哪些成员，rax 最后返回的是地址还是数值。

背诵句：struct 各成员分开，union 各成员重叠；结构体传值、传地址与隐藏结果地址要分别判断。

41. 指针、函数指针与地址传递

指针是地址，指针类型决定解引用读取什么类型，以及指针算术的步长。强制转换指针类型通常不自动把目标对象内容变成另一种数值，也不自动改善对齐或合法性。

&p 取得指针变量自身的地址；p 是它存的目标地址；*p 是目标对象。二级指针可以指向一个指针变量：先读出一层指针，再访问下一层对象。

null pointer 空指针表示不指向有效对象，不可解引用；它与“指向某个值为 0 的对象的指针”不同。局部变量生命周期结束后，指向它的指针失效；返回局部数组首地址不能延长数组的生命周期。

函数指针保存可调用函数的入口相关地址。AT&T 间接调用常写 call *%rax；直接 call f 与从寄存器读目标的 call *%rax 不同。

通过地址传参时，传递的是地址本身，call 不会自动复制地址所指对象。写入 (%rdi) 会修改所指内存，改写 %rdi 只会改变当前寄存器里的地址值。

背诵句：改指针值与改指针所指对象是两件事；地址传参不会自动复制对象。

42. 浮点数的机器级表示与指令

现代 x86-64 常使用 XMM 寄存器进行 float、double 标量操作。一个 XMM 寄存器有 128 位，但标量指令通常只把其中低 32 或低 64 位作为一个 float 或 double；不能把“寄存器 128 位”当成“double 变成 128 位浮点数”。

ss 表示 scalar single，单精度标量；sd 表示 scalar double，双精度标量。这里的 s、d 与整数 b/w/l/q 是不同的一套记号。

单精度 双精度 用途
movss movsd 传送标量浮点数
addss addsd 加法
subss subsd 减法
mulss mulsd 乘法
divss divsd 除法
ucomiss ucomisd 比较并设置整数条件码中的相关位
cvtsi2ss cvtsi2sd 有符号整数转浮点数
cvttss2si cvttsd2si 浮点数向零截断转有符号整数

cvtss2sd 是 float 转 double，cvtsd2ss 是 double 转 float。某些转换指令用附加宽度信息区分 32、64 位整数源或目的。

传统双操作数 SSE 的算术通常覆盖目的，如 subsd %xmm1,%xmm0 是 xmm0−xmm1。教材也可能出现以 v 开头的 AVX 三操作数形式，单独写目的，不能机械套双操作数覆盖规则。

浮点比较尤其要处理 NaN。对完成比较的 ucomisd / ucomiss，忽略异常而按正常完成后的结果看：

目的值与源值的关系 ZF PF CF
大于 0 0 0
小于 0 0 1
等于 1 0 0
无序 unordered（含 NaN） 1 1 1

PF 是 parity flag，在这里 PF=1 可表示无序。因此浮点比较后仅用 je，可能把无序误当作相等；完整判断要根据编译器生成的额外条件处理。整数有符号比较的 jl/jg 规则不能直接套到浮点比较。

背诵句：浮点常走 XMM；ss 单精度、sd 双精度；cvtt 向零截断；浮点比较要额外处理 NaN 的无序情况。

43. 补充：栈越界与防护

数组边界通常不会由普通机器访存指令自动检查。对栈上数组写出界，可能覆盖其他局部对象、保存的寄存器、栈保护值、返回地址，具体取决于实际布局。

常见防护机制：

  • 栈保护 canary：在敏感位置放保护值，返回前检查是否被破坏。
  • 地址空间布局随机化 ASLR：让某些地址随运行变化，增加准确预测地址的难度。
  • 不可执行内存 NX：禁止在相应数据页执行指令，阻止直接执行注入的数据。

这些措施分别针对不同环节，不能推导出“任何越界都一定被发现”。考试若只涉及机制说明，记住作用即可，不需要扩展到攻击实现。

背诵句：越界可能破坏调用状态；canary 检查破坏，ASLR 随机地址，NX 限制执行。

44. 补充：80 位扩展精度与 long double

Intel x87 的 80 位扩展格式常有 1 位符号、15 位阶码、1 位显式整数位、63 位小数字段。整数位是显式存储的，不同于 binary32、binary64 中规格化数的隐含前导 1。

其阶码 bias 为 16383，规格化有效精度为 64 位。不要把“80 位总长度”当作 80 位有效精度。

long double 的格式和 sizeof 依赖平台。某些 Linux x86-64 环境中使用 80 位有效格式，但对象占 16 字节，额外空间用于对齐和布局。其他环境可能与 double 相同或使用其他格式。

背诵句：80 位 x87 有显式整数位，有效精度 64；long double 的存储大小不直接等于格式有效位数。

第三部分：常见形式、易错点与直接背诵

45. 常见代码形式的含义

45.1 位操作形式

以下位操作以固定宽度 unsigned 类型为主要理解模型；窄整数提升、操作宽度与移位范围仍要按实际类型处理。

形式 含义或用途
!!x 把零/非零规范成 0/1
x ^ y 各位不同时为 1；结果为 0 表示位模式相同
x & (x−1) 清除最低的一个 1；x=0 时结果仍为 0
x & (~x+1) 保留最低的一个 1，其余位清零
x!=0 且 (x&(x−1))==0 x 是 2 的幂
x & (2^k−1) 获取低 k 位；对无符号数相当于模 2^k
(x>>k)&1 获取第 k 位，x 宜为无符号
x | mask 把掩码为 1 的位设成 1
x & ~mask 把掩码为 1 的位清成 0
x ^ mask 把掩码为 1 的位翻转

证明这些形式时，把最低的 1 前后的位拆开：一个数减 1，会把最低的 1 变为 0，把它右边原来的 0 全变为 1；与原数按位与就恰好清掉该最低 1。

按补码算术右移，x 右移 w−1 位可得到全 0 或全 1 的符号掩码。用全 0/全 1 掩码做选择时，可理解为 (mask & a) | (~mask & b)：mask 全 1 选择 a，全 0 选择 b。

若编写 C，需要确保这里的全宽掩码、取反和加一都处于预定类型中；用有符号 −x 构造最低 1 时，x=TMin 是必须单独考虑的边界。

45.2 汇编形式

形式 优先考虑的含义
xor %eax,%eax 清零 rax
test %r,%r 后接 je r 为零时跳转
test %r,%r 后接 jne r 非零时跳转
cmp $常量,%r 后接跳转 比较寄存器值与常量
lea 若干线性项 地址计算或常数乘法加法
setcc 后接 movzbl 构造完整的 0/1 结果
sar 到符号位 构造符号掩码
cqto 后接 idivq 对 rax 中的有符号数做除法
调整索引、检查范围、间接 jmp 可能是 switch 跳转表
地址计算后把地址放到参数寄存器 可能是按地址传参

这些是识别线索，不是仅凭一条指令就能唯一推断源程序。最终要看整个数据流、条件码和控制流。

45.3 浮点运算过程与位模式顺序

浮点加法的常见理解顺序：对阶 → 有效数加减 → 规格化 → 舍入 → 检查指数范围。对阶时把较小指数的有效数右移；有效信息可能落入被舍弃部分，所以小数可能被大数“吸收”。异号相加等价于有效数相减，可能需要向左规格化。

浮点乘法的常见理解顺序：符号异或 → 有效数相乘 → 指数相加 → 规格化 → 舍入 → 检查范围。这里相加的是实际指数 E；若直接使用编码阶码 e，必须修正 bias，不能直接把两段 e 相加当作结果阶码。

对非负且非 NaN 的 binary32 / binary64 编码，将位模式看成同宽无符号整数时，顺序与数值顺序一致。负数区域顺序相反；±0 数值相等却编码不同；NaN 必须另行处理。因此不能把所有浮点比较统一变成普通无符号整数比较。

46. 不同类型题目的固定处理顺序

这节只给方法，不附题目。

46.1 整数表达式

先记各变量类型和位宽 → 做整数提升 → 确定共同运算类型 → 在该类型中计算 → 判断回绕或未定义行为 → 按赋值目标进行最后转换。

遇到“判断恒等式总成立”时，优先考虑 0、−1、最小值、最大值、最高位为 1、符号转换、非法移位、有符号溢出。不要只用一般正数验证。

46.2 浮点表达式

先确认格式与精度 → 判断操作数类别 → 判断每一步的计算类型 → 对每一步考虑舍入、范围与 NaN → 最后分析比较或整数转换。

float 与 double 混合的普通算术常转为 double；两个 float 的普通算术类型通常仍是 float，具体额外中间精度另看环境。不要把所有浮点表达式都先当成无限精度实数计算。

46.3 顺序汇编

先写参数寄存器含义 → 为每个寄存器维护当前表达式 → 每条指令更新目的 → 对内存操作先算绝对地址 → 遇写 32 位寄存器立即清高 32 位 → 最后看返回寄存器或内存写入。

表达式变复杂时可给当前寄存器值起新名字，不要一直用最初的 x、y 代表已经被覆盖的寄存器。

46.4 控制流汇编

先找比较或 test → 确认操作数顺序 → 判断有符号/无符号 → 写出跳转的真实条件 → 标记各代码块出口 → 合并成 if、循环或 switch。

只要中间有一条修改条件码的指令，就重新确定后续跳转使用哪一次运算。

46.5 栈与过程调用

先记 call 前 rsp 的绝对地址 → call 后减 8 并标记返回地址 → 逐条累计 push/sub/add/pop → 给每个有效对象标绝对地址 → 在每个时刻按当前基准计算访问位置 → 返回前验证 rsp 和被调用者保存寄存器的恢复。

跨 call 保留的值，要明确由寄存器约定还是栈空间保证。只说“寄存器里还存着”不够。

46.6 数组与结构体

先确定元素/成员类型大小与对齐 → 写地址公式 → 对二维数组先写行间距 → 对指针数组先读行指针 → 对结构体逐成员对齐并做尾部填充 → 把汇编偏移与这些公式匹配。

48. 可以直接背的总提要

A. 数据表示与整数

  1. 数据由位模式保存，由类型解释；地址说明位置，内存内容说明值。
  2. 一个十六进制位对应四个二进制位，一个字节通常是八位。
  3. 小端低有效字节在低地址；x86-64 是小端。
  4. Linux x86-64 常用 int 4 字节、long 8 字节、指针 8 字节。
  5. w 位无符号范围 0…2^w−1；w 位补码范围 −2^(w−1)…2^(w−1)−1。
  6. 补码最高位权重 −2^(w−1)；同位模式最高位为 1 时，补码值等于无符号值减 2^w。
  7. 补码负数取反加一；全一是 −1；TMin 的同宽正相反数无法表示。
  8. 逻辑运算看零与非零，结果 0/1；按位运算逐位处理；&&、|| 短路。
  9. 左移低位补零；逻辑右移高位补零；算术右移高位补符号位。
  10. 零扩展保无符号值，符号扩展保补码值；截断只保留低位。
  11. 先提升，再确定共同类型，再运算，再转换到赋值目标。
  12. int 与同等级 unsigned int 混合，int 转 unsigned int；更宽有符号类型可能容纳较窄无符号类型。
  13. 无符号算术按模回绕；C 有符号溢出未定义。
  14. 补码加法同号结果反号才溢出；一正一负加法不溢出。
  15. 有符号减法在操作数异号、结果与被减数反号时溢出。
  16. 完整乘积最多 2w 位；同位模式有符号和无符号乘积的低 w 位相同。
  17. C 整数除法向零截断，余数与被除数同号或为零。
  18. 无符号除以 2^k 用逻辑右移；负数向零截断可先加 2^k−1，再算术右移。
  19. 移位数要在提升后的位宽内；机器计数屏蔽不能替 C 非法移位辩护。
  20. x&(x−1) 清最低一；x&(~x+1) 留最低一，注意实际运算类型。

B. 浮点数

  1. V=(−1)^s×M×2^E；存储字段是 s、e、f，e 不等于 E，f 不等于 M。
  2. bias=2^(k−1)−1。
  3. 单精度：1/8/23，bias=127，规格化精度 24 位；双精度：1/11/52，bias=1023，精度 53 位。
  4. 规格化：e 既非全零也非全一，M=1+frac，E=e−bias。
  5. 非规格化：e 全零，M=frac，E=1−bias；f 全零就是带符号零。
  6. e 全一、f 全零是无穷；e 全一、f 非全零是 NaN。
  7. 最小正非规格化数 2^(1−bias−n)；最小正规格化数 2^(1−bias)。
  8. 最大有限数 (2−2^(−n))×2^Emax；同指数区间间距 2^(E−n)。
  9. float 最小正非规格化 2^−149，最小正规格化 2^−126；double 对应 2^−1074、2^−1022。
  10. 范围看指数，精度看有效位数；所有绝对值不超过 2^p 的整数可精确表示。
  11. 默认最近偶数，恰好半数时选最低保留位为零；舍入可能再产生进位。
  12. 浮点加法对阶、加减、规格化、舍入；乘法符号异或、有效数相乘、实际指数相加，再规格化舍入。
  13. 浮点加法和乘法不普遍满足结合律，分配律也不普遍成立。
  14. NaN 不等于自身，有序比较为假；+0 和 −0 数值比较相等。
  15. 32 位 int 转 double 精确，转 float 可能舍入；64 位 long 转 double 可能舍入。
  16. C 浮点转整数向零截断；越界、NaN、无穷没有可依赖的合法整数结果。

C. 汇编与控制流

  1. AT&T 源在前、目的在后；$ 是立即数，% 是寄存器。
  2. b/w/l/q 分别是 8/16/32/64 位；movl 的 l 不代表 Linux C long 的宽度。
  3. 写 32 位寄存器清对应 64 位寄存器高半部；写 8/16 位仅改相应部分。
  4. 内存地址 D+base+index×scale，scale 只取 1/2/4/8，偏移按字节计。
  5. mov 读写数据，movs 符号扩展，movz 零扩展；lea 算地址数值而不读内存。
  6. 二元指令更新第二操作数，sub S,D 是 D−S。
  7. sal=shl；shr 补零；sar 补符号；可变移位计数常在 cl。
  8. 单操作数 mul/imul 的完整乘积在 rdx:rax；rdx 高、rax 低。
  9. div/idiv 的被除数是 rdx:rax；商 rax、余数 rdx；有符号 64 位除法常先 cqto。
  10. ZF 看零，SF 看最高位，CF 看无符号进借位，OF 看有符号溢出。
  11. cmp S,D 用 D−S，test S,D 用 D&S，二者不保存运算结果。
  12. mov、lea、not 不改条件码；inc、dec 不改 CF；跳转读最近有效的相关条件码。
  13. 有符号小于 jl：SF≠OF；小于等于 jle：ZF=1 或 SF≠OF。
  14. 有符号大于 jg：ZF=0 且 SF=OF；大于等于 jge：SF=OF。
  15. 无符号小于 jb：CF=1；小于等于 jbe：CF=1 或 ZF=1。
  16. 无符号大于 ja：CF=0 且 ZF=0；大于等于 jae：CF=0。
  17. 相等 je 看 ZF=1，不等 jne 看 ZF=0。
  18. setcc 只写一个字节；完整布尔值常再 movzbl。
  19. cmov 条件写目的寄存器，但不能普遍替代条件分支的安全求值。
  20. 循环找初始化、更新、条件和回跳；switch 表项可能是地址或相对偏移。

D. 过程调用与内存布局

  1. 栈向低地址增长，rsp 指向栈顶；push 通常减 8，pop 通常加 8。
  2. call 压下一条指令地址并转到函数；ret 弹返回地址并跳回。
  3. 函数预留空间减 rsp，回收空间加 rsp；ret 前 rsp 要指向返回地址。
  4. System V 整数/指针参数：rdi、rsi、rdx、rcx、r8、r9；普通整数返回 rax。
  5. 简单第七个整数栈参数在入口常是 8(%rsp)，入口 0(%rsp) 是返回地址。
  6. 被调用者保存：rbx、rbp、r12～r15；调用者保存的值若还要用，由调用者先存。
  7. call 前普通 rsp 对齐 16；入口 rsp+8 对齐 16；rbp 帧指针可省略。
  8. call 改变 rsp，已有局部对象的绝对地址不自动改变；其相对偏移会改变。
  9. 一维数组地址 A+i×L；二维连续数组地址 A+(i×C+j)×L。
  10. 指针数组访问先读行指针；连续二维数组直接按固定行宽算位置。
  11. 指针加一走一个目标对象；汇编地址偏移始终按字节。
  12. 结构体逐成员对齐、最后整体对齐；总大小包含填充。
  13. 联合体成员重叠，整体空间按最大需求与对齐确定。
  14. XMM 常存浮点参数与结果；ss 单精度、sd 双精度；浮点比较另处理无序 NaN。
